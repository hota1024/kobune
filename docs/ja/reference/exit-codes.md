# 終了コード

すべてのコマンドが「どういう種類の失敗か」を表す終了コードを返すので、
スクリプトやエージェントは出力を読まずに分岐できます。

| コード | 意味 | 再試行可能? |
| --- | --- | --- |
| `0` | 成功 | |
| `1` | それ以上特定できないエラー | いいえ |
| `4` | 見つからない（workspace / サービス / プロジェクト） | いいえ |
| `5` | 既に存在する | いいえ |
| `6` | `minato.toml` が見つからない | いいえ |
| `7` | `minato.toml` が不正 | いいえ |
| `8` | git リポジトリの外 | いいえ |
| `9` | コンテナランタイムに繋がらない | **はい** |
| `10` | ランタイムの操作が失敗した | いいえ |
| `11` | 未対応 | いいえ |

「再試行可能」とは、何も変えずに後でもう一度実行すれば成功しうる、という
意味です。該当するのは 9 だけで、Docker か Apple Container を起動してから
もう一度実行してください。

## `exec` は別です

`minato exec` は上の表ではなく、**実行したコマンドの終了コード** を返します。

```console
$ minato exec web -- npm test; echo $?
1
```

テストの成否が終了コードだけで分かるのはこのためです。上の表と同じ値が
コマンドから返ってきた場合は区別できないので、確実に判定したいときは
`--json` の出力を見てください。

## JSON では

```console
$ minato url nope --json; echo $?
{
  "error": {
    "code": "not_found",
    "message": "no service named `nope`. Available: web, api",
    "hint": "…"
  }
}
4
```

`error.code` が機械可読な名前で、終了コードはその数値版です。`hint` があれば、
次に何をすべきかが書かれています。

`--json` ではエラーも **stdout** に出るので、呼び出し側は 1 本のストリームと
1 つの終了コードだけを見れば済みます。
