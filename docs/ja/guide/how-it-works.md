# 仕組み

他のページで説明が付かない挙動に出会ったときに読むページです。

## 構成

```
  minato (CLI) ──────┐
  minato-desktop ────┼── Unix socket / JSON-RPC ──┐
  SKILL.md (agent) ──┘                            │
                                            ┌───────────┐
                                            │  minatod  │
                                            └─────┬─────┘
            ┌──────────────┬──────────────────┼──────────────┬─────────────┐
            ▼              ▼                  ▼              ▼             ▼
       DNS (:53)    Proxy (:80/:443)      Runtime      Env resolver     Tunnel
     *.localhost →   Host で振り分け    Docker / Apple   3 層 +       cloudflared
      127.0.0.1                                        シークレット参照
```

**daemon の API が製品の本体です。** CLI・デスクトップアプリ・Skill はいずれも
同格のクライアントで、独自のロジックを持ちません。1 つでできることは、
すべてでできます。

## なぜ daemon がいるのか

常駐が要るものが 4 つあります。80/443 を確保し続けるプロキシ、53 を確保する
DNS、scale-to-zero が依存するアイドル判定の時計、そして `cloudflared` の
プロセスです。終了する CLI にはどれもできません。

## リクエストの流れ

`https://web.feature-auth.myapp.localhost` を開いたとき。

1. **DNS。** macOS は `*.localhost` を自分では解決しません。Chrome は独自に
   解決しますが、`curl` / Safari / Node の fetch はしません。そしてエージェント
   は curl を使います。そこで daemon が DNS サーバを持ち、
   `/etc/resolver/localhost` がそれを指します。この DNS は接尾辞配下の
   *あらゆる* 名前に 127.0.0.1 を返します。環境が無い名前も含めてです。
   名前解決に失敗しても何も分かりませんが、プロキシまで届けば「どの workspace
   があるか」を書いた 404 が返るからです。

2. **TLS。** プロキシは SNI で要求された名前の証明書を、`~/.minato/ca/` の
   ローカル CA からその場で発行します。ワイルドカードでは足りません。
   `*.localhost` は `web.feature-auth.myapp.localhost` を賄えず、worktree が
   増えるたびに深さの違う名前が生まれるからです。利用者は CA を 1 枚
   信頼すれば、あとは考えなくて済みます。

3. **ルーティング。** プロキシは daemon が持つテーブルでホスト名を引きます。
   起動中のサービスにはアドレスがあり、停止中のサービスはアドレスなしで
   テーブルに入っています。「止まっている」と「存在しない」を区別する必要が
   あるからです。前者は起こし、後者は 404 です。

4. **起動。** 停止中なら起動します。ブラウザには約 1.5 秒後に自動リロードする
   ページを返し、それ以外は受け付けられるまで最大 120 秒待たせます。エージェント
   に 503 を返すと「サーバが壊れている」と読まれます。

5. **転送。** プロキシはアドレスに接続してバイトを流します。WebSocket の
   upgrade も通ります。HMR がそれに依存しており、upgrade は HTTP/1.1 の機構
   なので HTTP/2 は意図的に広告していません。

`Host` ヘッダは **書き換えません。** Vite などは Host を見て許可判定をするので、
アプリには開いた URL がそのまま見えます。

## 状態の正はどこにあるか

daemon は **実行中の状態をファイルに持ちません。** コンテナが生きているか、
どのアドレスを得たかは、コンテナ自身のラベル（`dev.minato.*`）から読みます。
daemon を再起動しても、一覧を 1 回取れば全部復元できます。

状態ファイルが持つのは 2 つだけです。どの worktree を Minato が管理しているか
と、それぞれに発行した URL ラベル。ラベルを永続化するのは、あとで命名規則を
変えても既存の workspace の URL が変わらないようにするためです。

状態のコピーが 2 つ存在しないので、クラッシュ後に突き合わせるものもありません。

## 命名

`feature/user-auth` → `feature-user-auth`:

1. 小文字化し、`[a-z0-9-]` 以外を `-` に置換
2. 連続する `-` を畳み、両端から除去
3. 63 文字を超えたら切り詰め、元の名前のハッシュを付ける
4. 既存の workspace と衝突する場合もハッシュを付ける

**区切り記号以外の文字が落ちた場合もハッシュを付けます。** `/` `_` `-` `.`
空白は区切りで、それ以外が消えたなら情報が失われています。これがないと
`feature/デモ環境` と `feature/検証環境` はどちらも `feature` になり、URL が
衝突します。日本語のブランチ名は現実に使われます。

## ランタイム抽象が隠しているもの

バックエンドの仕事は、サービスを 1 つ起動して、どこに届くかを返すことです。

```rust
pub struct RunningService {
    pub endpoint: SocketAddr,
}
```

Docker ではフォワードされた `127.0.0.1:49312`、Apple Container ではコンテナ
自身の `192.168.64.3:3000` です。プロキシはどちらか知りません。この戻り値
ひとつのおかげで、Apple Container の追加に設計変更が要りませんでした。
ポートフォワードを前提にした型なら、作り直しになっていたはずです。

## 特権ポート

1024 未満は root でないと bind できません。launchd が root として 53/80/443 を
bind し、daemon にはファイルディスクリプタだけを渡します。plist の `UserName`
により daemon 自体は利用者として動くので、作られるコンテナやファイルの所有者も
正しくなります。

macOS は systemd の `LISTEN_FDS` 規約を使わないので、`launch_activate_socket()`
を呼び、plist に書いた名前で fd を引きます。

`SockNodeName` に `localhost` を書くと、launchd は `::1` と `127.0.0.1` の
両方に socket を開きます。両方が重要です。macOS は `*.localhost` を両方に
解決し、クライアントは IPv6 を優先します。IPv4 だけで待ち受けていたとき、
たまたま `[::1]` にいた無関係のアプリにリクエストが吸われたことがあります。
